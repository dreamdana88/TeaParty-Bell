## 接下来：A3 Message Content 申请用的最小功能

目标是让正式小G宝能向 Discord 申请 `Message Content`。先做两件能当场演示的事：

1. CoC 本局团录
2. 在跑团频道里直接发送 `1d100`

这是申请用的最小范围。不要扩成完整技能检定。

代码已经按下面的边界接上，相关自动测试通过。Dev 服做过 KP 路径实测。申请材料还没写。两个开关默认关着。Session 可以记下身份时间段、退出时间段，以及团录附件发出后的 `transcriptDelivered`。那里没有消息正文。

### 开关

```env
MESSAGE_CONTENT_ENABLED=false
COC_TRANSCRIPT_ENABLED=false
```

只有 `MESSAGE_CONTENT_ENABLED=true` 才注册 `GatewayIntentBits.MessageContent`。Dev Bot 测试时打开。正式小G宝在审核通过前保持关闭。关闭时，现有 `/coc`、`/r`、Boost、顶帖都要照常。

不另加 `COC_TEXT_DICE_ENABLED`。文字 `1d100` 跟着 `MESSAGE_CONTENT_ENABLED`。`COC_TRANSCRIPT_ENABLED` 只决定结束时要不要做团录。申请演示时两个开关一起打开。

### 团录

只处理小G宝自己创建、并且状态是 `ACTIVE` 的跑团私密频道。

**团录处理范围：** KP / PL 消息正文、发言者、角色名、时间。

不建立持续消息正文存储。跑团期间 Discord 频道就是唯一原文。优先在结束时读取当前 Session 频道历史，并在内存里生成团录。若实现必须使用临时文件，发送完成后立即删除，禁止进入长期数据库。

申请表要能答：**不持久化存储 Discord Message Content 到 Discord 之外。**

Session 可以记下两类时间段，都不是消息正文：`transcriptSeats` 是谁在哪一段时间里担任 KP 或 PL，以及当时的角色名；`transcriptOptOutSpans` 是谁在哪一段时间里选择不记录。当前仍打开的退出会同步进 `transcriptOptOutUserIds`。

结束时：

```text
Session 运行期间
→ 不持久化聊天正文
→ 只在身份变化或退出切换时记下用户 ID 和时间

结束时
→ 从频道最新消息向前翻页，每页最多 100 条，一直读到 startedAt
→ 按消息发送当时的身份和退出时间段过滤
→ 有效发言每 2000 条分一卷；不超过 2000 条仍是单个文件
→ 内存生成 Markdown Buffer
→ 直接作为 Discord 附件发送
→ 释放内存
```

正常团录的边界是 `startedAt`，不是固定 2000 条。2000 只决定分卷大小。20000 是翻页的安全上限：还没读到开团时间就触顶时停止，并在第一卷写明只包含最近 20000 条频道消息。某一卷没发出时，频道里说明团录没有完整发出，然后照旧结束。不要为了重试把正文写进磁盘。

一条消息要同时满足：发送时不早于 `startedAt`，发送者当时是 KP 或 PL，并且不落在他的退出时间段里。转成 OB 之前的 PL 发言保留，成为 PL 之前的 OB 发言不进。已经开着、还没有身份时间段的旧局，仍按读团录时的名单整段计入。读历史失败时，在频道里说明团录没发出。

团录附件发出后，原来的结束流程照旧：恢复昵称、卸身份组、锁发言，48 小时后删频道。

团录只服务这一局，不建永久聊天库。

```md
# 《模组名》团录

[20:15] KP：
你们推开了地下室的门。

[20:16] 奈洛莉：
我先观察门后的情况。
```

### 团录退出

在 ACTIVE Session 中允许 KP / PL 选择从现在起不记录自己的消息，并允许之后恢复。这是时间段，不是整局删除：退出前已经会记入的发言还在，退出期间的不补进团录，恢复之后只记新的消息。

OB 本来就不进团录，不提供这项。

最小交互：`MESSAGE_CONTENT_ENABLED` 和 `COC_TRANSCRIPT_ENABLED` 都为 true 时，进行中的控制面板才增加「团录与隐私」。只开其中一个不出现这个按钮，也不能改退出状态。这是频道里的同一条面板，按钮文字不能按人切换，所以点下去只给本人看下一步：

```text
不记录我之后的消息 / 恢复记录我之后的消息
```

每人只改自己的时间段。KP 不能替别人退出。PL 转成 OB 再转回来时，还没关闭的退出继续有效。

### 自然消息骰子

只在 `ACTIVE` 跑团频道里生效。KP 或 PL 发送整句 `1d100`，小G宝回复一次。OB 发送 `1d100` 不触发。

```text
奈洛莉 🎲 1d100 = 63
```

PL 用本局角色名，KP 用显示名。这一阶段只认 `1d100`。不要做 `cc 心理学`、奖励骰、惩罚骰、其他骰式、技能卡。现有 `/r` 保持原样，随机逻辑继续用 `src/features/coc/dice/`，不要另写一套。

### 边界

Message Content 只给 CoC 房间用。不扫描普通频道。开关关掉之后，不要为了团录或自然骰去读自然消息正文。OB 的话不进最终团录。退出用户的话也不进。

不把聊天正文写入 Session JSON、临时目录或数据库。生成用的 Markdown 只留在内存里，作为 Discord 附件发回频道，然后丢掉。不得已写了临时文件的，发送一完成就删。

### 测试

至少覆盖：开关关闭时不运行；两个开关缺一个时不出现团录隐私；普通频道忽略；非进行中的团忽略；KP 和 PL 进团录；OB 不进；Bot 消息忽略；退出时间段里的消息不进，退出前后的仍在；PL 转 OB 前的发言保留、之后的不进；OB 转 PL 前的发言不进、之后的按当时角色名进；KP 发送 `1d100` 会掷；PL 发送 `1d100` 会掷；OB 发送 `1d100` 不掷；普通句子不掷；结束时从频道历史在内存生成 Markdown，并作为附件发送；Session 文件里没有消息正文，只有用户 ID、角色名和时间段；成功发送后没有留下团录文件。原有全量测试继续通过。

## 本批：绑定调查员技能骰点

只标成功／失败两种：最终骰点不超过技能值为成功，超过为失败。奖惩骰以选中值判定；不特殊处理 1 或 100，不细分大成功、大失败、普通／困难／极难成功，不增加难度判定。普通无技能骰点只显示结果。
整句 `1d100 演技`、`1d100 演技 奖励1`、`1d100 演技 惩罚2` 读取本人绑定调查员的 Session 技能快照；奖惩骰复用现有实现。
技能值按档案馆既定字段 base + growth + occupationPoints + interestPoints 计算。全名优先，技能名或专业简称仅唯一时接受；重名提示完整名称，不猜。
无角色、未知技能、数据异常时不掷骰。仅进行中的跑团频道启用自然技能骰点，OB 不触发；KP 未绑定角色不借用他人的角色卡。
普通骰点、奖励／惩罚骰与 /r 均使用两行回复：`**@玩家 祝骰运昌隆喵~！**`，然后骰点结果；技能额外展示技能名和「最终骰点/技能值 成功或失败」，例如 `演技：34/70 成功`。
团录保留本 Bot 的这类骰点回复，按被提及玩家在当时的 KP/PL 身份与隐私设置过滤；其他机器人或本 Bot 的管理消息不收入。
不读档案馆 SQLite，不写长期卡，不消耗 HP/SAN/MP/Luck，不做对抗、幸运消耗或战斗后果。

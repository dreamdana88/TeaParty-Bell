## 4. 属性与派生值

### 4.1 生成方式只是注释

属性注释写的是生成提示，不是人物卡上的自动掷骰：

```text
STR CON DEX APP POW     3D6×5
SIZ INT EDU             (2D6+6)×5
```

属性注释里的 `RANDBETWEEN(1,6)` 会在 Excel 重算时改数字。小G宝若提供「随机生成」，用自己的骰子模块，不调用会自己变化的表格函数。

属性旁的 `INT(属性/2)` 和 `INT(属性/5)` 是属性检定的困难、极难值。

### 4.2 会进规则引擎的派生值

这些是 A。人物卡只负责显示，算式在附表。

```text
HP        = INT((CON + SIZ) / 10)
重伤      = CEILING(HP / 2, 1)
MP        = INT(POW / 5)
SAN 上限  = 99 - 克苏鲁神话技能
困难      = INT(成功率 / 2)
极难      = INT(成功率 / 5)
```

当前理智 `N10`、今日损失、临时生命是格子里的数，不是公式。示例卡上的当前理智等于 POW。表把「满值」和「这一局打到现在的值」写在同一张卡上。小G宝的长期角色卡只保存建卡结果；这一局的受伤和理智损失不写回角色卡。

### 4.3 伤害加值与体格

附表用 `力量 + 体型`（单元格上的 STR 与 SIZ）：

```text
合计 <= 1      体格 0
<= 64          -2
<= 84          -1
<= 124          0
<= 164         +1
<= 204         +2
<= 284         +3
> 284           4，再加 INT((合计 - 285) / 80)
```

伤害加值文案：

```text
体格 -2  →  -2
体格 -1  →  -1
体格  0  →   0
体格  1  →  +1D4
体格  2  →  +1D6
体格 >2  →  +(体格-1)D6
```

体格 3 得到 `+2D6`，体格 4 得到 `+3D6`。这是 CoC 7 的伤害加值表，包含超过 284 之后每 80 点再加一档。分类 A。

### 4.4 移动力

```text
STR > SIZ 记 +1，相等记 0，小于记 -1
DEX 与 SIZ 同样比较
两项都是 +1  → 调整 +1
两项都是 -1  → 调整 -1
其余         → 调整 0

年龄 < 40     移动减值 0
年龄 >= 40    移动减值 = INT(年龄/10) - 3

护甲减值开关打开时，再减去防具表上的 MOV 惩罚

最终调整 = 属性调整 - 护甲减值 - 年龄减值
人物卡显示的 MOV = 最终调整 + 8
```

所以两边都高于体型是 9，都低于是 7，其余是 8，然后再减年龄和护甲。分类 A。护甲开关和防具查表是 B：规则里护甲可以降移动，这张表用下拉和开关把它做成可选项。

### 4.5 每小时回魔

```text
INT(POW / 100 + 1)
```

POW 不到 100 时是 1，满 100 及以上是 2。格子上的输入提示也是这么写的。CoC 7 常见叙述是每小时恢复 1 点魔法。这格是作者加的便利，分类 B。首版派生值按每小时 1 点；若要「高 POW 恢复 2 点」，单独确认后再做，不从这格默默带上。

## 5. 年龄

自动改数字的只有移动力，见上。

其余年龄效果是附表 `D39:D48` 的缩写，人物卡用年龄去挑选其中一句显示：

```text
15–19   力量体型共-5 E-5 L*2
20–39   教育进步*1
40–49   进步*2, SCD共-5 A-5
50–59   进步*3, SCD共-10 A-10
60–69   进步*4, SCD共-20 A-15
70–79   进步*4, SCD共-40 A-20
80–89   进步*4, SCD共-80 A-25
90+     用同一套缩写继续加码
```

这些字符串不是可执行公式。填了年龄不会自动把 STR 减 5。分类：缩写所代表的年龄规则是 A，但这格文字是 C。

小G宝不解析这句中文。年龄修正要写成明确的数值规则，并且在写进代码前对照使用者认定的七版文本把缩写展开。在那之前，车卡可以显示「这个年龄段需要做哪些检定和减值」，不偷偷改属性。

另有「自定义年龄补正」输入。那是 B，首版可以先只做标准年龄段。

```text
第 2 行   序号 0，清除职业模板，没有点数公式
第 3 行   自定义职业
第 4–232 行  命名职业，从会计师到密探
```

```text
94  EDU*4
49  EDU*2+MAX(STR*2,DEX*2)
24  EDU*2+APP*2
14  EDU*2+DEX*2
12  EDU*2+MAX(DEX*2,APP*2)
```

兴趣点在人物卡上是：

```text

```

信用评级范围是文本，例如会计师 `30-70`。分类 A 的数据，B 的展示。自定义职业要手填信用和最多 8 个本职技能，说明文字要求先问守秘人。

人物卡还有「剩余经历包点」。经历包是这张表的额外资源，不是七版核心建卡步骤。分类 B，首版不做。

## 8. 武器、防具、资产、疯狂

武器列表是静态目录：类型、技能、伤害、射程、贯穿、每轮、装弹、故障、时代、价格。人物卡选中类型后把这些列抄过来，成功率仍然用人物卡上对应技能的当前值。伤害里的 `DB`、`半DB` 是文字，由人读，不是自动代入伤害加值。

防具表、载具表没有公式。护甲值、MOV 惩罚、覆盖部位按名称查。

资产：人物卡把现金、住所、交通、奢侈品等加总，再和附表里按时代取出的「资产上限」比较。上限随 `1920s / 现代 / 其他` 切换。物价参考表里大量 `×20`，是 1920 年代和现代物价的换算便利。分类 B。首版保留武器和物品清单即可，物价换算和资产上限校验可以后做。

疯狂表两列：即时症状、总结症状，各约十条，序号 1 到 10。人物卡用序号显示「失忆、假性残疾、暴力倾向……」。正文是规则摘要。分类 A 的是「临时疯狂 / 不定性疯狂 / 永久性疯狂」这套判定框架；症状长文属于参考文本，首版骰子不必自动抽疯狂症状。

理智区还有表内提示：一天内损失当前理智的五分之一进入不定性疯狂；可选的精神固化。这些是规则摘要加可选项，首版检定模块只做技能成功率，不自动跑疯狂流程。

## 9. 数据验证、提示和隐藏区

```text

type=list     55 条

```

`any` 不是约束。作者用它挂输入提示，内容是技能说明、MP 恢复说明、法术填写说明。提示可以很长，而且写明可能与规则书不一致。

```text

```

`whole` 有几条 `formula1` 是 `1`、`0`、`9`、`32767`，不像完整的数值范围。不当成规则。

隐藏表：


年代表、毒剂、雷达图、时代新闻都在附表后半。它们服务查资料和导出文本，不服务检定。


486 个公式里，163 个是直接引用人物卡，65 个是「和基础值相同就输出 0」。它是给外部骰娘粘贴的视图。

不作为小G宝的存档格式。首版导入导出用 `*.coc7.json`。以后若要「粘贴到骰娘」，单独做导出，不读这张表的单元格。表内已有 `#REF!`，不能假设它现在是好的。

## 13. 对角色卡 Schema 的直接含义

存玩家决定的数，不存 Excel 坐标。派生值随时用同一套函数重算，避免表和库各算一次。

```text
characteristics     九项输入
occupation          id、名称、点数公式种类、信用下限上限、本职技能名
skills[]            名称、专攻名、基础值、成长、职业点、兴趣点
weapons[]           名称、类型、关联技能、数量
armor               名称与是否计入移动惩罚
```
